# Low-memory fight screening

The Streamlit runtime uses **OpenCV + ONNX Runtime**. PyTorch and torchvision are only installed for training; VideoMAE, YOLO, Qwen, TensorFlow, and paid API calls are not part of the runtime path. The detector uses an 8-frame MobileNetV3-Small + GRU classifier, a low-cost optical-flow candidate gate, and an ONNX INT8 export when validation shows that quantization stays within the configured accuracy tolerance.

The model is not trained for this project until you supply and label clips. The app intentionally reports that the classifier is missing rather than presenting untrained guesses as fight detection. Fight screening is a review aid, not a finding of intent or a crime.

## Project layout

```text
app.py                         Streamlit upload and result UI
detector.py                    Bounded-memory OpenCV and ONNX Runtime inference
fight_model.py                 MobileNetV3-Small + GRU architecture (training only)
training/train_fight_classifier.py  group-safe train, evaluate, export, quantize
requirements.txt               small deployment dependencies
requirements-training.txt      local training dependencies
training/data/                  your private videos and manifest (git-ignored)
models/fight_detector.onnx      selected deployment artifact (generated by training)
```

## Train the compact fight model

### Step 1: Build a representative labeled dataset

Create 2–5 second clips and label each `fight` or `non_fight`. Include genuine fights at different distances, camera angles, lighting, and crowd levels. Include hard negatives such as hugging, dancing, sports, play-fighting, arguments without contact, and people passing close together. Keep clips from the same original video/session under the same `group_id`.

Start with hundreds of clips from many independent recordings per class if possible. More diverse source videos are more useful than many near-duplicate clips. Do not put clips from one source video into different splits.

Create `training/data/manifest.csv`:

```csv
video_path,label,group_id,start_seconds,end_seconds
clips/cam01_fight_01.mp4,fight,cam01_fight_01,4.0,7.0
clips/cam02_hug_01.mp4,non_fight,cam02_hug_01,10.0,13.0
```

Paths are relative to the manifest file. `group_id` identifies the source recording, not the individual clip. `start_seconds` and `end_seconds` can focus the row on the labeled event; leave them empty to use the whole video. Each manifest row is treated as one labeled clip.

### Step 2: Install training tools locally

Use Python 3.11 or 3.12 in a separate environment. These packages are deliberately excluded from the Streamlit runtime:

```powershell
python -m venv .venv-train
.\.venv-train\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-training.txt
```

The first training run downloads the public ImageNet MobileNetV3-Small initialization. To train without downloading pretrained weights, pass `--no-pretrained` (this usually needs more labeled data).

### Step 3: Train and export

```powershell
python training/train_fight_classifier.py --manifest training/data/manifest.csv --epochs 12 --batch-size 2
```

The script separates train, validation, and test data by `group_id`, fine-tunes the compact temporal classifier, chooses the highest-precision validation threshold that reaches the requested fight recall (90% by default), exports FP32 ONNX, and attempts calibrated INT8 quantization. It writes validation and held-out test precision, recall, F1, false-positive rate, and confusion matrices to `models/fight_detector.metadata.json`.

### Step 4: Review metrics before deployment

Prioritize **fight recall** so missed fights remain low, while watching the false-positive rate. Review the clips behind false positives and false negatives, add examples from those cases, and retrain. Quantized and FP32 metrics are reported separately. The script selects INT8 only when validation recall and F1 stay within tolerance of FP32; otherwise it selects FP32. Keep the test split untouched until final comparisons. The optical-flow gate also affects recall, so compare results with your validation clips after changing `FIGHT_MOTION_GATE`.

There is no honest way to promise the same accuracy before this evaluation: results depend on the quality and diversity of your labels. Increase clips/epochs or use a larger training machine if validation is poor. Training is done locally; Streamlit only needs the selected ONNX artifact.

### Step 5: Deploy the artifact

Install only the small runtime dependencies in the Streamlit environment (`requirements.txt`). Add these generated files to the app branch/repository:

```text
models/fight_detector.onnx
models/fight_detector.metadata.json
```

Then deploy the branch containing the trained artifact. Do **not** add source training videos or `.pth` checkpoints to the deployment repository. Set `FIGHT_THRESHOLD` only if you deliberately want to override the validation-selected threshold.

## Run locally

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

For CPU usage, set `ONNX_THREADS=1` or `2`. The sample rate, window size, stride, and optical-flow gate can be adjusted with the `FIGHT_*` environment settings in `.env.example`; validate every change against the held-out videos before deploying.
